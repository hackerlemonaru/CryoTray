# FEATURES

Exhaustive catalog of CryoTray features. Check before planning or adding features to enforce zero duplication.

## Static docs landing page (`docs/`)

- **Custom 404 page**: `docs/404.html` keeps the site header and footer, offers recovery links to the home page, live demo, features, Windows download, and GitHub, and shows a dark “route monitor” panel with `404`, a lost-signal trace, and the requested path. It is bilingual EN/AR, follows the saved language, is marked `noindex`, balances the 1280 x 900 desktop viewport with the footer at the bottom, and stays within 320 px without horizontal overflow.

- **Randomized interactive preview**: Every load picks one of six device classes and randomizes a matching CPU model/core pair, max/effective clock, CPU power, CPU/GPU/SSD temperatures, GPU load/hotspot, SSD health, and RAM total (`15.9`, `31.9`, or `63.9 GB`) with coherent usage and cache splits. The visible scenario label names the sample; the compact 420 px window uses a 116 px hero, 92 px chart, and 40 px telemetry rows; and the cooling switch transitions between generated OFF/ON targets, with the shell themed blue on ON and orange on OFF. The app titlebar groups five reference-style control icons into one download link with a `Download for more` tooltip, and the dashboard includes GPU brand, power, hotspot, VRAM, fan, and a live sparkline plus separate SSD C/E rows.
- **Working chart windows and live drift**: The 1, 5, 10, 30, and 60 minute selector redraws a distinct history from 3,600 one-second samples and downsamples long ranges to 240 points. Every sensor tick nudges the rounded CPU, GPU, SSD, and stress temperatures, so the readout never stays on the same value in OFF or ON.
- **Mode-colored preview shell and chart history**: Cooling ON themes the frame to `#2B88D8`, the CPU hero to a `#227CAD` to `#1F6F9F` gradient, the chart surface to a `#2B6F92` border on `#0D171E`, and the fan ring and petals blue; OFF returns the `#C26A47` frame and orange hero. The title bar and telemetry rows stay dark. Each of the 3,600 stored samples carries its ON/OFF mode in a parallel history; segmented line and fill colors preserve past blue ON and orange OFF periods across every 1 / 5 / 10 / 30 / 60 window, while current dots follow the selected mode. The compact preview is 420 px wide with a 116 px hero, 92 px chart, 40/41/51/36/36 px telemetry rows, and 36 px SSD rows. Verified at 1280, 512, and 320 px in EN and AR.
- **Real-app tooltips**: Hover, keyboard focus, or click the CPU temperature, RAM, GPU, or SSD pills. The CPU bubble is white with `#E2E2E2` borders, `CPU00..` cells in a 4/6-column grid, every tied hottest core underlined, and a package-power footer. Each scenario generates its own hot cores, cold core, and temperature spread; every core is aligned to the live hero maximum, so the hero number, chart latest sample, and hottest core cannot disagree. The `Memory Breakdown` popover matches the WPF surface with seven rows, a `4 px` bar, installed total, and footer hint. GPU/SSD tooltips and both chart canvases also show live hover values; the cooling info button explains the plan in the same popover surface. Click pins; outside click, blur, pointer leave, and Escape close; popups stay inside the preview.
- **Laptop recommendation**: A visible note recommends the app for laptops and explains that lower heat and power draw can help extend battery life.
- **Short automatic stress preview**: On page load, the temperature test runs a 15 second modeled preview, switches Cooling ON at 7 seconds, and stops as Preview complete. Metrics and comparison cards stay pending until measured samples support them; the cards use steady measured samples and the chart shows both cooling colors. Start Test after the preview runs an open-ended manual test.

A detail strip reports package power, sample average/count, and time-to-peak. Each plan card adds its measured peak, average, and effective clock; the DELTA card adds temperature, power, and clock rows with percentages and a one-line summary. Toggle Cooling during the run; Stop decays the load. FPS controls and projections remain absent from the website.
- **Slop-free editorial pass**: Removed the hero platform eyebrow, all section kickers, and the six uppercase feature labels; headings now stand alone. Display tracking is capped at `-0.03em`, micro-labels use sentence case, the last wide feature panel alternates sides on desktop, and a visible note labels the feature panels as sample readings. The OFF switch label now passes AA contrast, and page-level controls use 44 px targets. Verified at desktop, 390 px, and 320 px in EN and AR with no visible overflow.

Renders version, date, installer/portable names and sizes, `.sha256` links, a copyable PowerShell verification command, and a SmartScreen explanation.

## Telemetry & Hardware Monitoring

- **1 Hz Background Polling (`HardwareMonitorService`)**: Polls CPU, motherboard, multi-GPU, storage, and Win32 `GlobalMemoryStatusEx` physical RAM sensors via LibreHardwareMonitorLib 0.9.6 plus PDH `% Processor Performance`. Uses `double.NaN` / `null` when sensors are unavailable rather than synthetic fallbacks.
- **Runtime PawnIO Driver Check & Recovery**: Checks `HKLM\SYSTEM\CurrentControlSet\Services\PawnIO`, shows actionable install/download banners in `MainWindow` and `SettingsWindow` when missing, and automatically reopens LHM once PawnIO is installed.
- **Primary GPU Selection & Per-GPU Telemetry History (`Settings > GPU`, `TelemetrySample`, `TelemetryRingBuffer`, `MainWindow`)**: Isolates telemetry per GPU, prioritizes GPU Core / D3D 3D load sensors, collects GPU core clock MHz and VRAM used/total MB into snapshots and diagnostics, defaults to Auto (discrete GPU priority), lets users pick any detected GPU via `PreferredGpuIdentifier`, and keys ring-buffer GPU temperature history per GPU identifier so switching GPUs never mixes chart or stats history.
- **60-Minute Ring Buffer, Charts & Expanded CSV Export (`TelemetryRingBuffer`, `TelemetryCsvService`)**: Stores 3,600 one-second samples in memory; powers CPU and per-GPU charts across 1, 5, 10, 30, and 60 minute timeframes with hover tooltips, unavailable-sensor states, ring-buffer CSV export (including `GpuHotspotC,GpuVramTempC,GpuFanRpm`), and live 1 Hz CSV logging from the `Tools` menu with clean stop/error reporting on write failure.
- **Storage Telemetry, SMART Health & Per-Drive Filtering**: Validates drive temperature range `(0, 150) °C`, displays drive temperature, SMART percentage health (`Good` / `Fair` / `Worn` / `Replace`), and model tooltip on the dashboard, with per-drive checkboxes (`Settings > Disk`, `ExcludedDrives`) to hide cold/external drives from the dashboard and disk temperature alerts.
- **Per-Core CPU Breakdown**: Maps direct Intel core diodes or weighted AMD CCD/Tctl temperatures into `CPU00..` cells in the hero hover bubble, underlining cores tied for hottest and showing package wattage.
- **GPU Detail Expansion (`Settings > View`, `MainWindow`)**: An optional details row under the GPU health row shows VRAM used/total, core and memory clocks, and a compact reported performance-limit reason. `ShowGpuDetails` is off by default; enabling it adds the row and adjusts the dashboard height. Values come from LibreHardwareMonitor `SmallData`, `Clock`, and `Factor` sensors and render `--` when the hardware does not expose them.
- **Read-only Motherboard Fan Speeds (`HardwareMonitorService`, `SystemInfoWindow`)**: Collects raw `SensorType.Fan` readings (including 0 RPM headers) from motherboard, controller, and their subhardware into `HardwareSnapshot.Fans`, lists only moving fans in System Information, and renders `--` when the driver reports none. `Settings > View > System information` toggles the row (`ShowFanSpeeds`, on by default).
- **Live Fan Health Panel (`FanHealthService`, `SystemInfoWindow`)**: Adds a read-only Fan health disclosure under Fan speeds, collapsed by default and opened by clicking the heading or its `>` chevron. It lists each motherboard header and the primary GPU fan, current RPM, state (`Watching`, `Armed`, `Idle at 0 RPM`, `Stopped`), arming or alert countdown, last alert time, and a **Test fan notification** button. **Hide idle fans** is on by default and filters `Idle at 0 RPM` rows while always keeping `Stopped` rows visible; unchecking it shows every header. Fan alerts open System Information, expand the panel, and highlight the affected fan.
- **Friendly Fan Names (`AppSettings.FanAliases`)**: `Settings > General > Fan names` maps each motherboard header and the GPU fan to an optional custom label. Aliases are saved in settings and applied consistently in the Fan health panel, moving fan-speed rows, fan notifications, and diagnostics; blank names fall back to the sensor label.
- **Fan Speed Diagnostics Filter (`SystemInfoWindow`)**: The Fan health disclosure keeps a local Hide idle state, preserves highlighted deep-link rows even when idle, and shows a localized empty-state message when every remaining fan is idle.
- **GPU Fan Health (`FanHealthService`)**: Feeds `HardwareSnapshot.GpuFanRpm` through the same arming and stop timer, using GPU load and GPU temperature for demand so idle zero-fan mode stays quiet. A single GPU RPM sensor is treated as one fan signal.
- **Storage Health Watch (`StorageHealthAlertService`)**: Optional notifications when a non-excluded drive enters `Worn` or `Replace`, or its SMART health drops by 10 points (including cumulative gradual wear tracked against a session baseline watermark), with a 10 minute cooldown and a **Settings > Disk** toggle (`StorageHealthAlertsEnabled`, on by default).
- **Tray Badge Metric Selector (`TrayIconManager`, `Settings > View`)**: Independent CPU and GPU badge values for temperature, load, or RAM percentage, using the existing digit palettes and renderer. Temperature remains the default.
- **Top Process Consumers (`ProcessUsageService`, `SystemInfoWindow`)**: A collapsed **Top processes** disclosure in System Information lists the six processes driving CPU or GPU load, with CPU %, GPU %, and working-set memory. CPU uses `TotalProcessorTime` deltas; GPU sums WMI `GPUEngine` `engtype_3D` utilization by PID. Sampling runs every 2 seconds only while the section is open, and the panel reports when GPU process counters are unavailable.

## Cooling Mode & Power Management

- **CryoTray Cooling Power Plan (`PowerPlanService`)**: Automatically imports and activates the embedded `CryoTray.pow` power scheme (`CryoTray Cooling`), syncing external Windows power-plan changes every 2 seconds, and cleanly deletes the scheme on uninstall via `/uninstall-cleanup`.
- **Battery Auto-Cooling Rule**: Optional `EnableCoolingOnBattery` (`Settings > General`) via `SystemEvents.PowerModeChanged` enables Cooling Mode automatically on battery and restores the normal plan on AC reconnect only when battery activated it.
- **Configurable CPU Cooling Controls**: Adjusts `PERFBOOSTMODE` (Disabled/Enabled) and `PROCTHROTTLEMAX` (50% to 100%) on the CryoTray Cooling plan, plus selectable normal fallback power plan.
- **Custom Global Hotkey Recorder (`GlobalHotkeyService`)**: Interactive shortcut recorder in `Settings > General` supporting `Ctrl`, `Alt`, `Shift`, and `Win` plus `A-Z`, `0-9`, or `F1-F12` via message-only `HwndSource`, with conflict detection feedback.
- **Safe Exit Behavior (`ConfirmExitWindow`)**: Optional `DisableCoolingModeOnExit` prompt that disables Cooling Mode and restores the normal power plan when exiting.

## Autopilot & Alerts

- **Toolhelp32 Process Scan & Fullscreen 3D Autopilot (`AutopilotService`)**: Scans running processes every 2.5 seconds via `CreateToolhelp32Snapshot`, temporarily pausing Cooling Mode while any whitelisted app runs or (optionally via `AutopilotPauseOnFullscreen`) when a fullscreen Direct3D/presentation/borderless game is active via `SHQueryUserNotificationState`. Optional `AutopilotForegroundOnly` restricts the whitelist branch to the current `GetForegroundWindow` process, so background launchers cannot hold Cooling Mode paused (`Settings > Autopilot`, off by default).
- **Temperature Alerts (`TemperatureAlertService`)**: Thread-safe per-component thresholds for CPU, GPU, GPU hotspot, GPU VRAM (hotspot/VRAM use `Math.Max(HighTempThresholdGpu + 15, 95)` °C), and non-excluded disks, with 10 minute cooldown, 3 °C re-arm hysteresis, mute toggle that clears stale state, bilingual alerts, and a test notification button.
- **GPU Hotspot-to-Edge Delta Watch (`TemperatureAlertService`, `Settings > General`)**: Optional warning when the primary GPU's hotspot stays at least a configurable gap (default 25 °C, range 15–40 °C) above its edge temperature for 5 minutes. A sustained large gap can indicate dried thermal paste or a mounting problem. A dip below the threshold restarts the 5 minute window, and after one alert the watch enforces a 30 minute cooldown. `GpuDeltaAlertsEnabled` is on by default; the threshold follows the selected temperature unit in the label and notification.
- **Fan Health Watch (`FanHealthService`)**: Arms each fan header only after 60 seconds continuously above 300 RPM, then raises a tray warning if it reads 0 RPM for 30 seconds while CPU or GPU load is at least 25% and its temperature is at least 60 °C. Headers that never spin are ignored, demand must persist for 15 seconds, suspend/resume clears state with a 60 second grace period, and each fan has a 10 minute cooldown. `Settings > General` toggle (`FanHealthAlertsEnabled`, on by default).

## System Tray & Companion Windows

- **Dynamic Tray Badges & Second-Launch Activation (`TrayIconManager`, `App`)**: Separate GPU (green) and CPU (coral/cyan) badges or one combined split badge showing temperature or `--`, owner-drawn dark `#1E1E1E` tray context menu + pause submenu (`#2D2D2D` hover pill, trailing `#29B6F6` checkbox, vector chevron, and Arabic RTL flip) with checkable `Overlay Click-Through`, and named `EventWaitHandle` activation so relaunching `CryoTray.exe` focuses the existing dashboard.
- **Dashboard (`MainWindow`)**: Tray-anchored or freely positioned dark window (`444 x 673` baseline) with animated six-petal vector cooling fan, keyboard-accessible `BtnCoolingToggle` and `BtnCpuTempCores`, CPU/GPU charts with a selectable GPU metric, optional GPU details row, RAM row, filtered SSD rows, dark owner-styled `ToolsContextMenu` CSV export/logging and About tab actions (zero white icon gutter), and optional Overlay/Autopilot rows.
- **Floating Telemetry Overlay (`OverlayWindow`)**: Always-on-top draggable pill with configurable opacity (0% to 100%), optional click-through `WS_EX_TRANSPARENT` pass-through (`OverlayClickThrough`), and selectable CPU, GPU, RAM, and battery metrics. Battery shows percentage plus `Charging`, `Full`, `Plugged in`, or `On battery`; it is omitted on desktops without a battery. The same status is appended to the CPU/GPU tray tooltip, with safe length clipping.
- **CPU Temperature Test (`StressTestWindow`)**: Multi-core CPU stress generator running on `BelowNormal` background worker threads with live temperature/clock readouts, 60-sample chart, inline Cooling Mode switch, and session CSV export (`Export CSV`).
- **System Information (`SystemInfoWindow`)**: On-demand WMI, EDID monitor, active NIC, Event 100 boot duration, BSOD count, drive matching (serial, disk index, model), Cooling-Mode-scoped CPU temp stats, a collapsed **Top processes** panel with CPU/GPU/memory by process, plain-text report export, and **Copy diagnostics** for a short support snapshot with app version, CPU, GPU, temperatures, RAM, fan states, and drive health. Copied diagnostics exclude serial numbers, PC names, and file paths.

- **Resilient & Protected GitHub Updater (`UpdateService`, `UpdateStorage`, `UpdateBackupService`, `UpdateCompletionService`, `UpdateStatusService`)**: Checks run every 5 minutes while the dashboard is visible and every 30 minutes in the tray, plus startup, resume, and network reconnect. Last-check state persists across restarts; a persisted **Available** shows **Check again** until the release object is fetched again. Installed copies are identified by a matching Inno uninstall key or an Inno `unins000.exe` marker under Program Files; portable copies remain portable in Program Files and use `CryoTray-Update-*.zip` from an administrator-protected folder. ## Deferred Features

- **GPU Power-Limit Control**: Evaluated and not implemented. Monitoring already exists through LibreHardwareMonitor (`GpuTelemetry`: temperature, hotspot, VRAM temperature, power, load, fan RPM). Reading the vendor power cap (NVML/IGCL, or ADLX through a shim) is a low-risk future addition; writing a cap is deferred because laptop and integrated GPUs are firmware-owned, AMD needs a native shim, and it conflicts with the documented no fan or voltage control boundary.
- **Multi-Monitor & High-DPI Window Placement (`WindowPlacementHelper`, `MainWindow`, `OverlayWindow`)**: Per-monitor DPI-aware `DockSideBySide` supporting negative-coordinate left/top monitors with 4-edge clamping, disconnected-monitor recovery for saved dashboard and overlay positions, and secondary-monitor preservation for the floating overlay.
- **Candidate GPU follow-ups (remaining)**: GPU driver/vBIOS/PCI/TDR diagnostics, read-only thermal headroom, and per-GPU chart coverage for additional sensor families. Per-GPU telemetry history, hotspot/VRAM alerts, the hotspot-to-edge delta watch, the chart metric switch, VRAM usage, clocks/throttle state, and expanded GPU CSV columns are implemented.
