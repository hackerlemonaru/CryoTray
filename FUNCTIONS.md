## App lifecycle

- `App.OnStartup` location guard: release-only (`#if !DEBUG`). Debug builds, and Release builds when `UpdateStorage.IsDeveloperModeEnabled` finds an administrator-created `dev-mode` marker, skip `UpdateStorage.IsSafeApplicationLocation` and `EnsureApplicationDirectoryProtected` so project output can run. Every configuration still secures the ProgramData update and rollback roots; update installation keeps its own guard.
- `App.DefaultCoolingOnFrameColor` / `DefaultCoolingOffFrameColor`, `ResolveFrameColor(string?, string)`, `NormalizeHexColor(Color)`: safely parse and normalize custom Cooling ON/OFF window frame accent hex colors.
- `App.ShowDashboard()`: creates `MainWindow` when absent, restores it above the tray, and activates it.
- `App.ToggleDashboard()`: closes the visible dashboard, otherwise calls `ShowDashboard()`.
- `App.ToggleOverlay()`: creates and shows `OverlayWindow` on enable; closes and clears the field on disable.
- `App.ToggleOverlayClickThrough()`: toggles `Settings.OverlayClickThrough`, saves settings, applies `WS_EX_TRANSPARENT` to `OverlayWindow` if open, and updates the tray menu state.
- `App.TrimWorkingSet()`: runs an aggressive GC, waits for finalizers, and calls `NativeMethods.EmptyWorkingSet` for the current process.
- `App.AvailableUpdate`, `PendingUpdateSuccess`, `UpdateAvailabilityChanged`, `ScheduleAutomaticUpdateCheck(bool)`, `TryRunAutomaticUpdateCheck(TimeSpan)`, `RunAutomaticUpdateCheckAsync()`, `OnDashboardVisibilityChanged(bool)`, `SetAvailableUpdate(ReleaseInfo?)`, `ConsumeUpdateSuccess()`: run a 5-minute dashboard check or 30-minute tray check, check immediately on startup, resume, and network reconnect, record `UpdateStatusService`, deep-link the tray notice to About with the release, and consume the one-time success marker.
- `App.RegisterHotkeyIfEnabled()`: creates a message-only `HwndSource` (`CryoTrayHotkey`) when Cooling Mode or RAM hotkey is enabled and registers/unregisters `CoolingHotkeyId` (`9001`) and `RamOptimizeHotkeyId` (`9002`).
- `App.TrySignalExistingInstance()`: signals the named `EventWaitHandle` (`CryoTray-Show-Dashboard-Event-99210`) when a non-`/autostart` second `CryoTray.exe` launch finds an active primary instance.
- `App.RegisterActivationWaitHandle()`, `UnregisterActivationWaitHandle()`, `ActivateDashboardFromSignal()`: listen for second-launch activation signals on a thread-pool wait handle and foreground `MainWindow`.
- `App.PauseCoolingFor(TimeSpan)`, `CancelCoolingPause(bool, bool)`, `CoolingPauseTimer_Tick()`, `IsCoolingPausedByTimer`, `CoolingPausedUntilUtc`: manage timed Cooling Mode pauses (`15m`, `30m`, `1h`), tray countdowns, manual/battery guards, and autopilot handoff; `StartupTaskService.EnsureSynchronized(settings.LaunchOnStartup)` heals moved `.exe` paths at startup.
- `App.EvaluateBatteryCoolingRule()`: handles `SystemEvents.PowerModeChanged` (`EnableCoolingOnBattery`) so battery power enables Cooling Mode (unless timed pause is active) and AC restores normal only when battery activated it.
- `App.ExitApplication()`: asks `ConfirmExitWindow` when the setting is enabled and Cooling Mode is active; otherwise stops pause timer, stops `MemoryOptimizerService`, unregisters both hotkeys, and exits without changing the power plan.
- `App.DisableCoolingForExit()`: safety net used by `OnExit` for other shutdown paths, including updates.
- `MainWindow.OpenSettingsDialog()`, `OpenSystemInfoDialog()`, `OpenStressTestDialog()`, `RunWithChildDialogGuard(Action)`: manage child dialogs cleanly and preserve `_isChildDialogOpen` across nested dialogs like CSV `SaveFileDialog`.

- `MemoryTelemetryService`: `TryReadBreakdown(out MemoryBreakdown)`, `ParseSystemMemoryListBuffer(ReadOnlySpan<byte>, int, out ulong, out ulong, out ulong)`, `FormatBytes(ulong)`, `ComputeCpuUsagePercent(...)`, `MeasureCpuUsageAsync(TimeSpan, CancellationToken)`: reads `GetPhysicallyInstalledSystemMemory`, `GlobalMemoryStatusEx`, multi-build variable-size `NtQuerySystemInformation(80)` (Win10 1809–Win11 26xxx), and `GetSystemTimes` CPU utilization.
- `HardwareMonitorService.ScoreGpuLoadSensor(string)`, `IsValidDriveTemperature(double)`: prioritize GPU Core / D3D 3D load over Memory/Video/Copy sensors and filter bogus drive SMART temperature bounds `(0, 150) °C`.
- `TelemetryRingBuffer.GetCpuStats(bool coolingOnly = false)` / `GetGpuStats(bool coolingOnly = false, string? gpuIdentifier = null)`: compute min/avg/max over finite `> 0` samples, optionally scoped to `CoolingModeActive == true` and a specific GPU identifier.
- `TelemetryCsvService.ExportSamples(IReadOnlyList<TelemetrySample>, string)` / `StartRecording(string)` / `StopRecording()` / `RecordingError`: invariant-culture CSV snapshot export (including `GpuHotspotC,GpuVramTempC,GpuFanRpm`) and live 1 Hz append logging that cleanly stops and reports write failures.
- `MemoryOptimizerService.Instance`: `OptimizeAsync(MemoryOptimizationTrigger, CancellationToken)`, `ExecuteKernelCommands(bool, bool, Func<int, (int, int)>?)`, `Start()`, `Stop()`, `Dispose()`, `IsOptimizing`, `LastResult`, `LastSuccessfulResult`: runs `RtlAdjustPrivilege(13)` + `NtSetSystemInformation(80)` (`2, 3, 4`), clipboard clear, tray toast notifications, and CPU-idle guarded auto-optimization.
- `TryReadMemoryMetrics(out double usedGb, out double totalGb, out double usagePercent)`: delegates to `MemoryTelemetryService.TryReadBreakdown`.
- `RefreshMemorySnapshotNow()` & `CloneSnapshot(HardwareSnapshot)`: clones `CurrentSnapshot` (preserving `CpuVendor`, every primary `Gpu*` telemetry field including VRAM, clocks, and throttle, and `Gpus`), refreshes RAM breakdown fields immediately, and notifies telemetry subscribers.
- `ReadHardware()`: one poll tick. Updates CPU, motherboard, per-GPU telemetry (`ReadGpuTelemetry`, `ResolveGpuVendor`), storage nodes (`CreateDriveTelemetry` + `ReadDriveMetadata`), and physical RAM, reopens LHM if PawnIO becomes installed, and sets `double.NaN` when sensors are absent. `CollectFanSensors(IHardware, List<FanTelemetry>, HashSet<string>)` recursively reads non-GPU fan sensors with non-negative RPM values up to `20000` (including `0 RPM` for health tracking) and deduplicates them by hardware identifier plus name.
- `ReadCpuRegistryInfo()`, `ResolveCpuVendor(string?, string?)`, `ResolveGpuVendor(HardwareType, string?)`: reads processor name, `VendorIdentifier`, and nominal MHz from the central processor registry key (plus WMI `Manufacturer`), mapping real CPU and GPU vendors cleanly without hardcoding fallback brands.
- `CleanCpuName(string?)`: removes `\b\d+-Core\s+Processor\b` suffixes across arbitrary core counts and trailing `Processor` labels.
- `ReadHardwareNamesFromLhm()`: fills CPU name from the opened LHM hardware list.
- `CollectCpuSensors(IReadOnlyList<ISensor>, CpuSensorSet)`: filters invalid temperatures and classifies per-core, package, CCD, load, and clock sensors.
- `ResolvePeak(CpuSensorSet, double?)`: hottest CCD Tdie, then Tctl/Tdie, then hottest CPU reading, then motherboard, else `null`.
- `ResolveFloor(double)`: `peak - 3.5`, clamped, so the bubble keeps a 3.5 C span.
- `BuildCoreTemperatures(CpuSensorSet, double, int)`: Mode A direct sensors plus Mode B fill.
- `BuildWeightedTemperatures(CpuSensorSet, double, double, int)`: 70 percent load plus 30 percent clock activity, min-max normalized, scaled between floor and peak.
- `SampleMax(IReadOnlyList<double>, int, int)`: groups contiguous sensor values when sensor count differs from physical core count.
- `CreateCoreTelemetry(int, double)`: builds `CPU00...` with raw and display temperatures.
- `GetKindOrder(string)`: P-Core 0, E-Core 1, Core 2.
- `UpsertCoreTemperature(...)`, `UpsertCoreValue(...)`: dedupe same core key, keep the higher value.
- `Start()`, `Stop()`, `Dispose()`, `RingBuffer`, `CurrentSnapshot`, `TelemetryUpdated`.

## Updates and storage

- Release status (2026-11-19): `v0.0.103` is the public latest release, published from `aa2d167` by run `44629021389`. The `v0.0.102` prerelease test completed the installed `0.0.101` to `0.0.102` update through the setup helper, completion marker, and restart path. The successful path has no code defect; a complete rollback backup exists, but rollback and failure recovery were not exercised live. The updater functions remain the only path for checks, downloads, helper launch, rollback, and completion markers; Inno is not a substitute for them. The old `v0.0.100` updater prefers any ZIP asset and failed its real upgrade test, so `v0.0.100` users need one manual setup run.
- `UpdateStorage.EnsureUpdateRoot()`, `EnsureRollbackRoot()`, `SecureDirectory(string)`, `EnsureNoReparsePoints(string)`: create `%ProgramData%\CryoTray` with an Administrators owner and protected Administrators/SYSTEM DACL, reject reparse points, recursively secure children, clear untrusted root contents, rotate the log, and expose protected paths.
- `UpdateStorage.IsSafeApplicationLocation(string)`, `EnsureApplicationDirectoryProtected(string)`: reject an elevated app location whose folder owner is untrusted, whose folder or parent chain grants standard users write/delete/change-permission/take-ownership rights, or which contains a reparse point; then set an Administrators owner and protected Administrators/SYSTEM/Users-read-execute DACL on the app folder and every child.
- `UpdateService.GetLatestReleaseAsync()`, `DownloadAsync()`, `LaunchUpdater()`, `LaunchRollback()`, `ParseExpectedSha256(string?, string?)`, `SelectAsset(JsonElement, bool)`, `ValidateUpdateManifest(...)`, `IsSafeRelativePath(string)`: conditional GitHub API checks with `X-RateLimit-Remaining`-aware 403/429 handling, filename-matched SHA-256 verification, strict asset classification rejecting uninstaller EXEs, lock-aware stale download cleanup, DOS device & trailing-dot/space path rejection, UTF-8 BOM PowerShell 5.1 helper with PID start-time guard, 3-attempt copy retry, and rollback marker cleanup.
- `UpdateService.GetDownloadCacheSizeBytes()`, `ClearDownloadCache()`: measure and remove downloaded update files under the protected `Update\Downloads` root, skipping or unlinking reparse entries without following them. About exposes the size and a guarded **Clear downloads** action.
- `UpdateBackupService.CreateBackup()`, `GetCurrent()`, `VerifyBackup()`, `VerifyCurrent()`, `DeleteCurrent()`, `GetSizeBytes()`: write rollback copies with a SHA-256 file manifest, reject unexpected or modified files, verify before restore, measure the backup for the About display, and let About delete the current rollback copy after confirmation. `CreateBackup()` rotates the rollback root: after writing the new manifest it deletes every other backup directory, so the prior rollback version is removed only on the next backup creation. `DeleteCurrent()` removes only the manifest-selected backup inside the protected rollback root and then removes `backup.json`.
- `AppSettings.SaveRollbackOnUpdate` / `SettingsWindow.ChkSaveRollbackOnUpdate`: default-on setting that controls whether `InstallUpdateAsync` creates a rollback copy before launching an update. When off, the updater receives an empty backup path and cannot automatically restore on failure; existing backups are not deleted by the setting.
- Rollback safety: call `UpdateStorage.EnsureRollbackRoot()` before reading or launching a rollback, and `EnsureUpdateRoot()` before reading the completion marker. `GetCurrent()` and `LaunchRollback()` now enforce the rollback guard; `ReadPending()` enforces the update guard. `SecureDirectory()` rechecks reparse points after creating a missing directory.
- `UpdateCompletionService.RecordPending()`, `ReadPending()`, `MarkApplied()`, `Clear()`: store the from/to versions and one-time update ID in protected ProgramData and expose the success marker only after the helper records `AppliedUtc` and the new version matches.
- `UpdateInstallationService.IsInstalled()`, `IsInstalledAt(string)`: choose installer or portable updates from a matching Inno uninstall key, or an Inno `unins000.exe` marker under Program Files; a portable copy under Program Files without the marker remains portable.
- `UpdateStatusService.Restore()`, `Record()`: restore and persist the last checked time, outcome, version, and detail in `AppSettings`, then raise `Changed` for About.
- `MainWindow.BtnToolsMenu_Click`, `ToolsContextMenu_Opened`, `MenuToolsStress_Click`, `MenuToolsExportCsv_Click`, `MenuToolsRecordCsv_Click`, `MenuToolsAbout_Click`, `RenderWpfContextMenusForTest()`: drive declarative dark `ToolsContextMenu` (`RamDarkContextMenuStyle` + `DarkMenuSeparatorStyle`), sync RTL `FlowDirection` and recording label state, open dark `Settings > About`, and support pixel verification alongside `RamScopeMenu`.

## Diagnostics & Verification
