## Architecture

- Developer launch: `App.OnStartup` applies `UpdateStorage.IsSafeApplicationLocation` and `EnsureApplicationDirectoryProtected` only in non-Debug builds, and Release builds skip both when `UpdateStorage.IsDeveloperModeEnabled` finds `%ProgramData%\CryoTray\dev-mode`. The property secures that root before checking, so only an administrator can create a marker that survives. Update installation and the updater helper still reject a user-writable app folder. `/test`, `/test-updates`, `/dump`, and `/uninstall-cleanup` run before the guard in every configuration.

- `App.xaml.cs`: software-rendered, single-instance WPF shell with named `EventWaitHandle` (`CryoTray-Show-Dashboard-Event-99210`) second-launch window activation, `SystemEvents.PowerModeChanged` battery auto-cooling and fan-health suspend/resume rules, `/uninstall-cleanup` CLI mode, tray manager, message-only hotkey `HwndSource`, on-demand `MainWindow`, App-owned overlay, and working-set trimming; `/dump` bypasses the mutex and writes `cpu-sensors.txt`.
- `Views/MainWindow`: 444 x 673 baseline dashboard (dynamically adjusts height for `PawnIoBanner`, `RamRow`, `GpuHealthRow`, `GpuDetailsRow`, `OverlayRow`, and `AutopilotRow`), hero CPU card, six-petal animated vector cooling fan, CPU and GPU charts with hover cards and unavailable states, a GPU chart metric switch (`Temperature`, `Power`, `Load`), dedicated timeframe strip, cooling toggle, RAM/CPU/GPU telemetry rows, an optional GPU details row (VRAM use, clocks, performance limit), filtered SSD rows, per-core hover popup, and `Tools` menu CSV export/live 1 Hz logging. Created per open and destroyed on close or deactivation (guarded by `RunWithChildDialogGuard` during dialogs).
- `Views/OverlayWindow`: App-owned translucent HUD created when overlay is enabled, supporting Win32 `WS_EX_TRANSPARENT` click-through pass-through, optional `RamOverlayGroup`, and optional `BatteryOverlayGroup` (`Width` 430 when CPU+GPU+RAM visible, else 360; `+70` when battery is shown, max 500). Battery uses `BatteryTelemetryService` and is omitted when no battery is present or `ShowBatteryStatus` is off.
- `Views/SettingsWindow`, `StressTestWindow`, `SystemInfoWindow`: companion windows created per open. `SettingsWindow` includes General (battery cooling rule, temperature alert mute and GPU hotspot-gap alert plus threshold, Fan Health Watch toggle, dynamic Fan names alias editors, interactive hotkey recorder `TxtHotkeyShortcut`), View (frame colors, Black/White tray badge digits, CPU/GPU badge value selectors, GPU details toggle and graph metric selector, RAM row, overlay click-through/RAM, battery percentage toggle hidden without a battery, motherboard fan speed row), CPU (clock/base speed, Large/Small graph), Memory (RAM cleaner & auto-optimization rules), Disk (master toggle, storage health watch, per-drive hide & inline graphs), GPU, Autopilot (fullscreen 3D pause and foreground-only checkboxes), and About. `SystemInfoWindow` adds a live Fan health disclosure under the fan speed row, collapsed by default and opened from its header or `>` chevron, with a default-on Hide idle filter, a **Copy diagnostics** button, a test notification button, and a fan-highlight deep link that expands the panel. It also adds a collapsed **Top processes** disclosure that samples CPU and GPU load every 2 s only while open. `StressTestWindow` runs stress workers on `ThreadPriority.BelowNormal` background threads so 1 Hz polling stays responsive and supports session CSV export.
- `Views/ConfirmExitWindow`: app-styled Yes/No confirmation shown when exiting would disable Cooling Mode.
- `Services/HardwareMonitorService`: 1 s background poll of LibreHardwareMonitor with runtime PawnIO detection (`HKLM\SYSTEM\CurrentControlSet\Services\PawnIO`), automatic reopen if PawnIO is installed later, per-GPU telemetry isolation, primary GPU selection (`AppSettings.PreferredGpuIdentifier`), LHM storage metadata caching, drive exclusion key helpers (`GetDriveExclusionKey`, `IsDriveExcluded`), and zero-WMI RAM telemetry (`GlobalMemoryStatusEx`). Produces `HardwareSnapshot` (including per-GPU temperature/load/power and read-only non-GPU fan RPM in `Fans`) and appends `TelemetrySample.FromSnapshot` to a 3,600-sample ring buffer.
- `Services/TelemetryCsvService`: invariant-culture CSV snapshot writer and continuous 1 Hz file logger fed by `TelemetryUpdated`.
- `Services/PowerPlanService`: imports and switches the CryoTray Cooling power scheme, and deletes it cleanly via `PowerDeleteScheme` + `powercfg /delete` fallback on uninstall (`/uninstall-cleanup`).
- `Services/AutopilotService`: process-whitelist polling every 2.5 s using Win32 `CreateToolhelp32Snapshot` plus optional fullscreen game/presentation detection via `SHQueryUserNotificationState` and borderless monitor-rect check. `AutopilotForegroundOnly` resolves the current foreground PID through `GetForegroundWindow` + `GetWindowThreadProcessId` and limits the whitelist branch to that process.
- `Services/FanHealthService`: stateful fan watchdog fed by each `HardwareSnapshot`; arms motherboard headers and the primary GPU fan after 60 s above 300 RPM and raises `FanStopped` for armed fans that read 0 RPM for 30 s under sustained demand. Motherboard fans use CPU-or-GPU demand; the GPU fan requires GPU load and GPU heat. Clears state on suspend/resume with a 60 s grace and throttles each fan to one alert per 10 minutes. `GetStatuses()` exposes `Watching`, `Armed`, `Idle at 0 RPM`, or `Stopped` plus arming/alert timing for the UI; `GetDisplayName(...)` resolves `AppSettings.FanAliases` with a safe fallback.
- `Services/BatteryTelemetryService`: reads WinForms `SystemInformation.PowerStatus` into `BatteryTelemetry` (`HasBattery`, `Percent`, `IsCharging`, `IsOnAc`) and returns localized `Charging`, `Full`, `Plugged in`, or `On battery` state labels. Shared by the overlay, tray tooltip, and Settings toggle; no WMI polling.
- `Services/ThemeService`: normalizes `AppSettings.Theme` to `Dark`, `Light`, or `System`, resolves `System` from `HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize\AppsUseLightTheme`, swaps 73 shared brush resources in `Application.Current.Resources`, and raises `ThemeChanged` on the UI dispatcher. Listens for `SystemEvents.UserPreferenceChanged` (`General` / `VisualStyle`) while `System` is selected. `WindowBorderBrush` remains user-defined and outside the palette.
- `Services/StorageHealthAlertService`: optional SMART watchdog fed by each `HardwareSnapshot`; alerts when a non-excluded drive enters `Worn` or `Replace`, or its health drops by 10 points, with a 10 minute per-drive cooldown.
- `Services/SystemInfoQueryService`: lazy WMI, EDID, boot, and BSOD queries. Matches LHM storage telemetry to `Win32_DiskDrive` via serial, physical disk index, and model, and queries Cooling-Mode-only CPU temp stats.
- `Services/ProcessUsageService`: on-demand process sampling for the System Information panel. CPU percentages come from `Process.TotalProcessorTime` deltas normalized by elapsed wall time and logical processor count; GPU percentages come from `Win32_PerfFormattedData_GPUPerformanceCounters_GPUEngine` rows whose instance name contains `engtype_3D`, summed per PID. It keeps the previous sample in a static gate, returns the top six processes by peak CPU/GPU, and is called only while the disclosure is expanded.
- `Services/WindowPlacementHelper`: shared per-monitor DPI-aware window placement utility (`GetMonitorWorkAreaDips`, `GetWorkAreaForSavedPositionDips`, `FindTargetWorkArea`, `ClampToWorkArea`, `ComputeSideBySidePosition`) used by `MainWindow` (`PositionAboveTray`, `UpdateWindowHeight`, `DockSideBySide`) and `OverlayWindow` (`ClampToWorkArea`) for negative-coordinate multi-monitor setups and disconnected-monitor recovery.
- `Services/NativeMethods`: Win32 P/Invokes hardened with `[DefaultDllImportSearchPaths(DllImportSearchPath.System32)]` (`EmptyWorkingSet`, `CreateToolhelp32Snapshot`, `Process32FirstW`, `Process32NextW`, `CloseHandle`, `SHQueryUserNotificationState`, `GlobalMemoryStatusEx`, `GetSystemPowerStatus`, `NtQuerySystemInformation` raw buffer overload, `PowerDeleteScheme`, `GetForegroundWindow`, `SetForegroundWindow`, `GetWindowRect`, `GetWindowThreadProcessId`).
- `Tray/TrayIconManager`: GPU, CPU, or merged split tray badges (`--` when unavailable, skipping redundant HICON redraws via signature checks), independent temperature/load/RAM badge metrics, optional battery percentage/state suffix in all tooltips (`ComposeTooltip` keeps the 63-character limit), and dark context menu including checkable `Overlay Click-Through`.

## Domain rules

- Unavailable numeric telemetry (`CpuTemp`, `PeakCpuTemp`, `MaxCoreTemp`, `CpuGhz`, `CpuBaseGhz`, `CpuMaxGhz`, `CpuLoad`, `GpuTemp`, `GpuLoad`, `RamUsedGb`, `RamTotalGb`, `RamUsagePercent`, `DriveTelemetry.Temperature`) uses `double.NaN` (and `null` for `int?` / `double?`), never synthetic values; UI renders `--` or an unavailable message.
- `snapshot.CpuTemp` is the integer display max across mapped cores when finite sensors exist (`double.NaN` when unavailable). Hero, tray badge, overlay, chart, and stress test all check `double.IsFinite(v) && v > 0`.
- `snapshot.PeakCpuTemp` is the raw sensor peak before per-core mapping (`double.NaN` when unavailable).
- Ignore CPU temperature sensors containing `Distance to TjMax` or `SoC`.
- Peak prefers the hottest CCD Tdie when present, then Tctl/Tdie, then the hottest CPU reading, then motherboard CPU reading.
- Direct per-core sensor mapping is used only when no AMD `Tctl/Tdie` sensor exists.
- Floor is `peak - 3.5` so the bubble keeps a compact few-degree span.
- Per-core sensor names are matched by `^(?:CPU\s*)?(P-Core|E-Core|Core)\s*#\s*(\d+)$`.
- Hottest cores are every core whose `DisplayTemp` equals the maximum.
- Popup columns are 4 up to 16 cores, 6 above 16.
- Primary GPU Auto mode prefers discrete GPUs (NVIDIA, non-APU AMD, Intel Arc) with valid temperature over integrated graphics; users can override via `AppSettings.PreferredGpuIdentifier` in `Settings > GPU`.
- Storage telemetry pairs with WMI drives by normalized serial number, then `PhysicalDriveNumber`, then model name + closest capacity, never by positional index.
- Excluded storage drives (`AppSettings.ExcludedDrives` keyed via `HardwareMonitorService.GetDriveExclusionKey`) are omitted from `MainWindow` SSD rows, `TemperatureAlertService` disk notifications, and `StorageHealthAlertService` health alerts.
- `SystemInfoQueryService` CPU temp stats (`System_TempStats`) report `CoolingModeActive == true` samples only (`TelemetryRingBuffer.GetCpuStats(coolingOnly: true)`).
- Hotkey recorder accepts standalone `F1-F12` or modifier (`Ctrl`/`Alt`/`Shift`/`Win`) + `A-Z`, `0-9`, or `F1-F12`.
- Motherboard fan sensors are collected from non-CPU, non-GPU, non-storage hardware and their subhardware, deduplicated by hardware identifier plus sensor name; raw non-negative readings including 0 RPM are retained in `HardwareSnapshot.Fans`, while `FormatFanSpeeds` hides stopped headers and renders `--` when no fan is moving.
- Fan Health Watch arms a header only after 60 s continuously at or above 300 RPM. It alerts only after 30 s at 0 RPM, and only when CPU or GPU load is at least 25% together with a temperature of at least 60 °C sustained for 15 s. Headers that never spin stay inert, recovery resets arming, suspend/resume clears state with a 60 s grace, and a 10 minute per-fan cooldown limits repeats. `FanHealthAlertsEnabled` defaults to true. Display aliases are resolved through `FanHealthService.GetDisplayName` so panel rows, alert text, fan-speed lines, and diagnostics stay consistent.
- The primary GPU fan (`HardwareSnapshot.GpuFanRpm`) is one health signal regardless of how many physical fans the card exposes. It arms and stops on the same timers, but its demand gate is GPU load at least 25% and GPU temperature at least 60 °C; CPU-only load does not alert it. Idle zero-fan mode therefore remains `Idle at 0 RPM`.
- `ShowGpuDetails` defaults to false. When enabled, the GPU details row reads `GpuVramUsedMb` / `GpuVramTotalMb`, `GpuCoreClockMhz` / `GpuMemoryClockMhz`, and `GpuThrottleReason`; each renders `--` when the sensor is absent. `GpuGraphMetric` defaults to `Temperature` and accepts `Power` or `Load`; the chart uses 30–90 °C for temperature, 0–100% for load, and a 50 W-rounded dynamic ceiling for power.
- GPU hotspot delta alerts require `GpuHotspotTemp` and `GpuTemp` to be valid. The gap must stay at or above `GpuHotspotDeltaThresholdCelsius` (default 25, Settings 15–40) continuously for 5 minutes; any dip below the threshold restarts the window. After an alert, a 30 minute cooldown applies. This alert uses the same tray notification gate as the absolute temperature alerts.
- Fan status precedence is `Armed` when spinning, then `Stopped` for an armed fan reading 0 RPM, then `Idle at 0 RPM` for a header that has never armed, then `Watching` for any other observed reading. `GetStatuses()` also exposes `LastAlertUtc`, spin/zero timestamps, and `IsGpuFan`.
- `StorageHealthAlertsEnabled` defaults to true. A drive alerts on first observation in `Worn` or `Replace`, on transition from `Worn` to `Replace`, or on a health drop of at least 10 points from the previous reading. Repeated warning readings and drops inside the 10 minute cooldown are ignored.
- CPU and GPU tray badge metrics persist as `Temperature`, `Load`, or `Ram`; `Temperature` is the default. Temperature values honor Celsius/Fahrenheit, load and RAM render as percentages, and unavailable telemetry renders `--`.

## Stress Test Retained Throughput

- **Per-Phase Iteration Accounting (`Views/StressTestWindow.xaml.cs`, `Models/TelemetrySample.cs`)**: Each `BelowNormal` stress worker owns a `long` iteration counter and publishes it with `Volatile.Write` every 1024 loops. `TakeIterationRate` sums the counters at each 1 Hz telemetry tick, divides by elapsed stopwatch seconds, and stores the result in `TelemetrySample.StressIterationsPerSecond`. ## GPU Control Evaluation

- **Vendor mapping**: NVIDIA uses NVML (`nvml.dll` in `System32`, `nvmlDeviceSetPowerManagementLimit`, documented and thread-safe); NVAPI power-limit writes are undocumented low-level calls and are not a supported path. AMD uses ADLX (ADL OverdriveN is legacy); ADLX is a C++ COM-style interface, so C# needs a native shim. Intel uses IGCL (`ControlLib.dll` in `System32`, `ctlOverclockPowerLimitSetV2`, 64-bit only, units from `ctlOverclockGetProperties`).
- **Telemetry is already covered**: `HardwareMonitorService` reads GPU temperature, hotspot, VRAM temperature, power, load, and fan RPM through LibreHardwareMonitor into `GpuTelemetry`. Vendor APIs are only needed to read or write the power cap, not to monitor thermals.
- **Decision**: no power-limit write path in the core app. Read-only capability and current/min/max values are the acceptable scope if the feature is revisited. Rationale: laptop and integrated GPUs are firmware-owned, three vendor backends include one native shim, and writes change the product's stated no-control boundary.
- **Write-path rules if approved later**: desktop discrete GPUs only, clamp against a fresh vendor min/max query, verify by readback, restore the default on dispose and on unhandled exception, serialize all vendor calls off the UI thread and the 1 Hz poll loop, and fail soft when the DLL or capability is missing.
- **Loading rule**: the portable elevated build must resolve vendor DLLs from `%SystemRoot%\System32` through `NativeLibrary.TryLoad`, never by bare `DllImport` name; an attacker-writable app folder would otherwise win the DLL search order with admin rights.
